# TableX のセキュリティガイダンス

TableX はローカルのデータベース GUI クライアント（Tauri + Rust バックエンド / React + TypeScript フロントエンド）です。
DB 接続情報・認証情報・任意 SQL の実行・AI 連携を扱うため、以下の観点を重点的にレビューしてください。

## SQL / データベース

- ユーザー入力やテーブル名・カラム名を文字列連結で SQL に埋め込まないでください。プレースホルダ（バインドパラメータ）を使用してください。
- 動的にテーブル名・識別子を組み立てる場合は、許可リスト検証か適切なクォート（識別子エスケープ）を必ず通してください。
- `format!` / テンプレートリテラルで組み立てた SQL 文字列をそのまま実行するコードは、インジェクションの疑いとして指摘してください。

## 認証情報・シークレット

- DB のパスワード、接続文字列、API キーをログ（`println!`・`eprintln!`・`log::*`・`console.log`）に出力しないでください。
- 接続情報やトークンをコードにハードコードしないでください。設定ストア/シークレットストアから読み込んでください。
- エラーメッセージやフロントエンドへ返すレスポンスに、生の認証情報や完全な接続文字列を含めないでください。

## Tauri コマンド境界

- `#[tauri::command]` はフロントエンドから到達可能な信頼境界です。ここで受け取る引数（パス・SQL・接続 ID 等）は信頼できない入力として検証してください。
- 任意のファイルパスを受け取って読み書きするコマンドは、パストラバーサル（`..`）を検証してください。
- エクスポート/インポート機能でユーザー指定パスを扱う際は、書き込み先を検証してください。

## フロントエンド (React / TypeScript)

- `dangerouslySetInnerHTML`・`.innerHTML =`・`document.write` によるユーザー由来データの描画は XSS の疑いとして指摘してください。
- クエリ結果やスキーマ名など DB 由来の値を HTML として直接挿入しないでください。

## AI 連携

- AI プロバイダ（Claude / Ollama）へ送るプロンプトに、ユーザーの認証情報や機微データを不用意に含めないでください。
- AI が生成した SQL をユーザー確認なしに破壊的操作（DELETE/DROP/UPDATE 等）として自動実行しないでください。

これらはレビュアー向けの追加ガイダンスであり、決定論的なガードレールではありません。
